## 已确认原因及对应修改

| 反馈 | 实际证据 | 修改 |
| --- | --- | --- |
| API key 正确却提示用量无法确认 | 用户本地两个作业收到 HTTP 200 后，响应体读取约 63.5/63.7 秒失败；配置超时为 60 秒，没有拿到 usage，下一次答案请求在发送前被预算保护拦住 | DeepSeek Flash 识别任务禁用默认思考，校核使用低思考强度；新建配置默认超时 240 秒，已有配置保持原值；提示区分缺失用量与真的达到额度 |
| 兼容服务只有总量仍停请求 | 原记账要求输入/输出分项齐全，并丢弃 `total_tokens` | 保留可信总量，未拆分部分单独记账；明确 HTTP 拒绝不污染下一次请求；已受理但超时的未知用量仍保守停止；前端显示总量 |
| 补字段失败、题目截断 | 日志有缺 cardinality、flowchart steps；默认关闭完整诊断时，补字段流程读不到刚被拒绝的候选 | 共享 per-slot 回答补明确的一选一约束；短期保留当前拒绝候选供一次补字段使用；递归处理流程图、表格和列表内容；明确输出截断错误 |
| 云端补出的原文没有用上 | 新回归复现：归一化最终总是优先本地 passage，覆盖有效云端正文 | 保留非空云端 passage，缺失才回退本地；继续走来源差异校核和采纳保护；同步重写段落映射、内容 ID 和答题位置引用 |
| Heading 答题位置错误/重复 | 本地题目提示与正文共用节点 ID；云端新段落 ID 又不能正确绑定 | 提示节点单独编号；拖入位置只出现在原文段落前；允许绑定候选自身真实段落；罗马数字答案保存为选项库的原始大小写 |
| 后续校核仍阻止导出 | 实际 Pearls 稿的 A–K 选词范围未被指令签名识别，误报缺字数限制；段落信息匹配使用 paragraphMap，但 runtime compiler 要求显式选项 | 指令范围补齐 A–K；编译时仅为没有显式选项/库引用的段落信息匹配，从真实段落映射生成运行选项；缺映射仍阻止导出，错误库引用不会被覆盖 |
| 答案页“无法核验，没有写入答案” | 首次真实 DeepSeek 测试识别出 13 个候选答案，但证据全部引用 pageIndex=1；实际提交的是原文件第 5、6 页，故全部拒绝写入 | 请求明确原始页码、禁止按附件顺序重编号；校验提交页集合；若引用错误，仅允许一次受预算约束的纠正请求；不猜测改写证据页码 |
| 版本是否最新无法判断 | 历次产物一直标 0.1.0，仅凭版本号无法确认；旧 exe 含有近期功能，不能认定它一定过期 | 设置页显示 revision、工作树修改状态、构建时间；新安装包由本次修改构建 |
| 检查时闪退 | 发布 profile 为 abort，而调度器期待工作线程 panic 可捕获恢复 | 发布改为 unwind，启动时安装位置/回溯日志钩子，日志不记录 panic 的文档/密钥载荷 |

“用量无法确认”不等于已经用了 30 万 token：它表示某个可能已收费的请求没返回可确认用量，系统无法安全判断后续请求会不会超额。API key、模型名和服务地址正确也不能保证完整文档请求在原先 60 秒内读完。小连接测试和完整 PDF 导入的负载不同。
