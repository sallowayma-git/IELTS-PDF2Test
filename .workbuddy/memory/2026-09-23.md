## 本机环境的关键发现（重要，别再踩）

**「WebView2 CDP 在本机不可用」是误判**，两层原因叠加：

1. **交给 App 的子进程环境被污染** → DevTools 端点根本起不来。
   修法：`tauri-cdp-harness.mjs::sanitizedAppEnv()` 清掉 `HTTP(S)_PROXY`/`ALL_PROXY`、
   `__COMPAT_LAYER`、`PATH` 里空项与不存在的目录。
2. **本沙箱下 WebView2 renderer 需要 `--no-sandbox --disable-gpu`**，否则启动约 7s 后
   renderer 崩掉：**DevTools HTTP 端点消失、App 进程仍然活着**。
   - `tauri-cdp-smoke.mjs` 的**默认值**就是这两个开关，注释里写着「环境必需」。
   - `tauri-cdp-single-file-import.mjs` 默认**不带**（`cdp-default`），所以在诊断档才跑得通。
   - 带诊断参数的运行记 `runProfile=cdp-diagnostic`，**不得**写成「默认产品路径通过」。
   - 诊断手法：`tmp/probe-app-exit.mjs`（只 spawn exe + HTTP `/json/list` 轮询，**不建 WebSocket**），
     带/不带 `PDF2TEST_AUTOMATION_SOURCE_FILES` 两次对照逐行同形 → 排除该变量是诱因。
   - 另一个坑：WebView2 会**重建 page target**，旧 WebSocket 随之关闭。
     `TauriCdpSession` 现在会 `attachToPageTarget()` 重新附着（`evaluate` 里自动重试一次），
     否则报错会伪装成「页面 90s 内未渲染出可见文本」，把人往「前端没渲染」方向带偏。

## F-Q2-3 根因（已定位，部分已修）

题目：group-5 `Choose FOUR correct answers, A-F`、group-6 `Choose FIVE correct letters, A-G`
被识别成 `multiple_choice` + `unordered_set` + **`options=0`/无 `optionBank`** ⇒ 界面上没有可作答控件。

完整因果链（一条根因引出四个症状）：
1. `authoring_pipeline::detect_dynamic_group_kind` 对这类题干落到 **`short_answer`** 兜底
   （`is_dynamic_multi_choice_text` 只覆盖 two/three）→ 该值作为 `kindHint` 进入
   `infer_instruction_signature` → `task_type_conflict:instruction=multiple_choice;structure_hint=short_answer`
   → `quality.rs:1954` 见 `recognitionWarnings` 里有该前缀 ⇒ **`TASK_TYPE_CONFLICT`（blocking）**。
2. `instruction_signature::infer_task_type_from_cues` 把 choose-four/five/six 判成 `MultipleChoice`。
3. `mod.rs:282` 的 `detect_option_bank` **带 `matching_semantics` 门**：
   `matches!(task_type, Matching*|Classification)`。类型是 `multiple_choice` ⇒ **门关着** ⇒ 选项库恒为 None。
4. 于是 `OPTION_RUN_INCOMPLETE`；且 `quality.rs:2456-2463` 的 `shared_multiple_choice` 分支要求
   `response_option_count(group,response) > expected`（= 选项数要多于 4），0 > 4 为假 ⇒ **`RESPONSE_GROUP_POLICY_MISMATCH`**。

**注意 `quality.rs:2313`**：若只把类型改成 `matching_*` 而不真正挂上选项库，
报错码会从 `OPTION_RUN_INCOMPLETE` **改名成 `OPTION_BANK_MISSING`** —— 只是换了个名字，阻断仍在。

本轮已修（先红后绿，2 个签名用例已绿）：
- `infer_task_type_from_cues`：choose-four/five/six **且题干声明字母区间** ⇒ `MatchingFeatures`
  （加区间条件是为了不吞掉阅读侧真正是单选题的 `Choose TWO letters, A-E`）。
- `detect_dynamic_group_kind`：新增 `is_dynamic_shared_letter_bank_choice_text` ⇒ `"matching"`。
- `infer_instruction_signature` 的冲突检查：**`short_answer` 是分类器的兜底、不是正向证据**，
  作 `None` 处理（正向提示如 `table_completion` 仍照旧报冲突）。
