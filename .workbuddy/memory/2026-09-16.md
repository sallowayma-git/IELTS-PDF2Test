### 2. 待办语义统一（R2）

  `resolution != AutoFixed && status ∈ {Open, Failed}`。`build_view` 的 `actionable` 与调度器

### 3. 内容变化后 resolution 失效（R3）

两条不同轴的判据，**不可互相替代**：

  里，现已抽出并接为唯一来源。
- `applied_answer_still_in_place`（写入**后**审计）：取 `proposed_patch` 的 `setAnswer.value`
  （**不是** `undo.value`，那是被覆盖的旧值）与当前权威稿比较。
- 呈现层：`build_view` 把「已写入但目标此后被用户改动」的 `Accepted` 项改以
  `Superseded` + `USER_EDITED_AFTER_APPLY` 呈现。

  `Accepted`，只靠前端隐藏入口挡不住直接调用命令的客户端。

### 4. 撤销闭环持久化（R5）

### git 仓库已修复（更正上面「环境坑」一节）

`git status` 曾报 `fatal: not a git repository`，根因三层叠加：`.git/refs` 目录整体缺失、
`objects/pack/` 下两个**只有 `.idx` 没有 `.pack`** 的孤儿索引（中断 fetch 残骸）、对象库大面积缺失。
`git config --local http.version HTTP/1.1` + 绕过代理后 `git fetch --refetch origin` 补齐对象，
再手工创建 `refs/remotes/origin` 并写入引用。现状：**87 个提交历史恢复、fsck 零缺失、`git diff` 可用**。
**副作用**：旧 `index` 引用了永久丢失的本地对象，只能重建 ⇒ **原有暂存状态丢失，需重新 `git add`**。
