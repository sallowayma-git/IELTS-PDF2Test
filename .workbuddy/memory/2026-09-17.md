### 收口时发现并修掉的回归（重要教训）

`source.rs::suggested_in_local_shape` 的 `_ => None` 把 `answer_kind` 非 `text`/`option`
的情况（典型是本地值为 `{"kind":"unresolved"}`）一律判成「无法映射」，于是**A3 之前就存在**
的这条路径被静默掐断：**本地空值 + 原文有可读答案行 ⇒ 建议补全**。

后果连锁：自动补空候选消失 → 依赖组结构校验降级路径永不触发 → 三个既有用例变红
（`empty_answer_is_auto_filled_only_when_the_source_asserts_the_value`、
`batch_that_breaks_structure_downgrades_the_whole_group`、
`reconcile_without_a_frozen_baseline_refuses_to_auto_apply`）。

修法：非 `option` 一律回落文本形状（与 A3 之前逐字一致），`option` 分支保留
「抽不出字母标签就返回 `None`」（空 labels 是形状垃圾，不是建议）。
教训：**「本地无值」时不存在可沿用的形状，此时形状对齐不是收紧而是误伤**；
改共用内核时要先确认它在**所有既有调用点上**是否与旧行为等价。

### A3 的安全边界（可复用的设计约定）

- 模型**只补确定性缺口**：只处理 `verdict == NotVerifiable` 且本地有值的槽位；
  确定性已成立时模型**根本不被调用**。
- 模型通道**没有** `suggested` 结论，只有 `confirmed` / `contradicted`——
  不让模型「发明新答案」。
- 每条断言必须带非空 `quote` + 1-based `pageIndex`；网关整份拒绝 + 判定层二次拦截。
- `SourceFindingV1::deterministic` 标记来源；自动应用守卫只读
  `SourceVerificationV1::deterministic_suggested`，模型建议**不解锁自动写入**。
- 状态按**合并后**的 findings 重算；`model_status`（NotRun/Succeeded/Unusable/
  BudgetExhausted）是独立字段，不靠链 status 反推；预算耗尽不复用「模型不可用」语义。
- **预算按通道各持一份**（调度器两个独立 `Cell`）：核验先跑，共用额度会让核验吃光裁决配额，
  那不是有界而是裁决通道在生产路径上静默失效。单次导入真实上限 = 2×2 = 4。
- `SourceVerifyRunner` **不接收 `document_ir`**：模型必须读原文件本身，
  递本地识别产物等于开一条「拿本地输出当原文证据」的捷径。

### Stage 2 修掉的真实 bug（重要）

`undo_cloud_repair_run` 回填时对**所有**目标都用 `replace_object_by_id`，但
`answerKey:<slotId>` 目标在稿件里是「以 slotId 为键的对象条目」，条目**内部没有任何身份字段**，
按 id 找对象永远找不到 ⇒ 槽位对象放回去了、**答案值还是模型写的那一份**。
失败形态极隐蔽：界面报「已撤销」，内容却没回来，比不能撤销更坏。
修法：回填统一走 `write_change_value`（它自己分派 `answerKey:` 前缀）。
**教训：`answerKey` 条目必须单独记账、单独回填，不能与槽位对象走同一条路径。**

### 一个刻意的设计决定：硬失败基线必须自洽

`apply_cloud_edits` 的「本次是否引入新机械错误」基线**不再读库里那份 `quality.hardFailures`**，
而是用同一套质量管线在**未施加本次编辑的 clone** 上重算。
原因：库里那份可能是播种/迁移时写下的、与当前内容不同步的旧结果，于是判据退化成
「库里那份质量块新不新」，一批与本次修复无关的旧差异就能把一次有效修复顶掉——
正是任务书要避免的「有一个问题就整卷修不动」。

### 环境新事实

- **PowerShell 的文件删除被沙箱拒绝**：`Remove-Item` 直接 exit 1，且**什么都没删**
  （与之前「报错但实际已删」的 `SAFE_DELETE_FAIL_CLOSED` 不同）。仓库根目录的
  `_*.log` / `_*.txt` 临时日志因此清不掉；好在它们被 gitignore，不会进提交。
- PowerShell 读 git 输出会把 UTF-8 中文显示成 GBK 乱码，但那只是**显示**问题；
  命令前加 `[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()` 即可正确读回。
- 同一文件在一批消息里并行发多个 Edit **仍会互相覆盖**（本次 `capture_change_targets`
  的签名改动 + `group_roots` 的 `mut` 移除都被静默吞掉，两次编辑都报成功）。
  同文件多处修改必须**串行**，且每步改完立刻 grep 复核。
